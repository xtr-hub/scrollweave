# Release status — ScrollWeave Python/Rust 0.9.5

**Rust-core Python library; release candidate verified on Windows (Rust 1.93.1, Python 3.12.7). PyPI publication is performed by the GitHub Release workflow using trusted publishing.**

Runtime dependency declarations: zero Python packages and zero third-party Cargo crates. Compilation requires installed Rust/Cargo and a platform linker. Native reconstruction algorithms are implemented in Rust source; Python manages ctypes/copies only.

Verification on Windows: `cargo test --workspace --all-targets` passes 36 tests, Python `unittest` passes 32/32 with no skips, `tools/smoke_test.py` passes against the source tree with native ABI v5, the shipped 3-frame fixture reconstructs its 120x330 truth page byte-exactly with known positions, and the CLI stitch output is pixel-exact. The 15-frame regression remains MAE 0.1267 / exact 99.819% with masks and MAE 0.1822 / exact 99.728% without masks. The 120-page deterministic headless-Chrome corpus passes **120/120 automatic and 120/120 known-geometry**: exact truth width/height on every page, zero missing pixels, max MAE 0.069 / min exact 99.848%, median MAE 0.000 / median exact 100% over 446,559,168 compared pixels. A 20-URL real-site smoke run captured 19 pages: browser-viewport + automatic positions passed 16/19, known geometry 10/19 and pure automatic 9/19; remaining primary failures were dynamic/sticky-overlay pages (`w3.org/WAI`, `numpy.org`, `nodejs.org`) and `gnu.org` timed out during navigation. Version 0.9.5 adds arbitrary-URL crawling with same-origin discovery and lazy-content warm-up, per-page capture retry/failure isolation, tall-page and frame-count guards, single-frame/short-page handling, four-side chrome detection for opaque/gradient/glass headers, horizontal capture-drift alignment, multi-candidate photometric/row-signature matching, adjacent-first graph initialization, and missing-scroll-position interpolation. Full research-prototype numerical parity, 30/UI/Japanese suites and cross-platform CI verification are still NOT established. JPEG/video/HEIC/OCR and semantic segmentation are not supported. This is not a production-certified full UI restoration binary. Refer to `PORT_STATUS.md` for detailed differences and acceptance tests.
